# AppDock.at365

自作の常駐ツールを**Applet**としてまとめて使う、Windows x64向けのアプリです。Appletの有効化、設定、ショートカット、トレイ操作をひとつの画面で管理できます。

## 動作環境・起動

配布された `AppDock.at365.exe` を、書き込み可能な好きなフォルダに置いて起動してください。AppDock自体のインストールは不要です。通常の.NETホストは、利用するPCにインストール済みの **.NET 10 Runtime（Windows x64）** を使用します。Node.jsの別途インストールは不要です。

.NET 10 RuntimeがないPCでは、[Microsoftの.NET 10ダウンロードページ](https://dotnet.microsoft.com/download/dotnet/10.0)から「.NET Runtime」のWindows x64版をインストールしてください。.NET 10 SDKや.NET 10 Desktop Runtimeが入っているPCは、含まれる.NET Runtimeを利用できます。`dotnet --list-runtimes` に `Microsoft.NETCore.App 10.0.x` が表示されることを確認してください。追加の動作環境が必要なAppletは、そのAppletの案内に従ってください。

0.26.17はElectron 44.6.0を使用します。EXEと対応Appletを更新して再起動すると、Appletの画面を本体のページとして利用できます。Gmail 0.9.2は本体ページと別ウィンドウの両方に対応します。

この配布版は未署名です。

## マウスジェスチャー

割り当ては同じジェスチャーごとのグループに表示します。左端のハンドルをドラッグ、またはフォーカスして上下キーでグループ内の順番を変更できます。異なるジェスチャー同士の順番は調整不要です。有効・無効はスイッチ、複製・削除は行の「…」から開くドロップダウンで操作し、削除は確認後に行います。外側のクリックやEscapeでメニューを閉じられます。

「割り当てを追加」を押すと共通のコマンドパレットが開き、入力による絞り込み・上下キー・Enterで選択できます。選択用のパレットではコマンドを実行しません。ピン留めも利用でき、割り当てと一緒に「変更をすべて保存」で確定します。通常の実行用パレットではEnterで実行します。

「設定 → マウスジェスチャー」で、AppDock本体やAppletのコマンドへ割り当てます。右ボタンを押しながら上下左右へ移動して離すか、左/中クリック・ホイール上下・キーを押すと実行します。単一方向の移動を認識し、方向転換や対象変更でキャンセルします。操作せずに離すと普通の右クリックに戻ります。

条件はグローバル、Webブラウザ、指定したexe、AppDock全体、すべてのApplet、提供元のApplet、指定したApplet。複数の割り当てが一致すると一覧順に実行し、同じコマンドは1回です。グループ内の並べ替え・複製・スイッチで整理できます。キーはCtrl/Alt/Shift付きや英数字、Fキー、対応特殊キーを指定します。WinやOS専用キーは対象外です。

対象ブラウザexeは共通一覧で変更でき、Chromium制限をオフにすればFirefoxなども指定できます。操作コマンドへの対応はブラウザによります。除外exe、移動距離、ホイールの最小実行間隔、待機表示の位置・不透明度も設定できます。本体コマンド「マウスジェスチャーを一時停止／再開」は実行するたびに状態を切り替え、本体再起動で解除します。トレイへの配置やショートカット割り当てができ、トレイでは一時停止中にチェックが付きます。右ドラッグを使うアプリには除外または一時停止を使ってください。

WebBrowserToolsの従来設定は初回に引き継ぎ、コマンドと送信キー設定はそのまま使えます。Applet側の入力処理は本体が停止して二重実行を防ぎます。WebBrowserTools 0.3.0以降との組み合わせを推奨します。入力補助プロセスに必要な.NET/WPFは本体EXEへ同梱し、Desktop Runtimeの追加インストールは不要です。他のジェスチャーソフトとの競合や、管理者権限アプリへの送信制限には注意してください。
## 基本の使い方

初回起動でEXEの隣に `settings.json` が作成されます。「設定」からフォームとJSONの両方で編集できます。ウィンドウの×は既定でトレイへ格納します。完全終了はトレイメニューの「終了」です。この動作は設定で変更できます。

AppDock内のテキスト入力では、スペルチェックを無効にしています。

設定とAppletページは、ページ上部の「変更をすべて保存」で未保存の変更をまとめて保存します。Appletの説明・設定・ショートカット・ログを切り替えても保存欄の位置は変わらず、別のAppletを選んでも選択中のタブを維持します。並べ替えも同じ保存欄で確定します。

未保存のままホーム・ログ・Gmailなどへ移動すると、ウィンドウ上部に黄色の通知が浮かびます。本文の位置は動かず、表示中のページを確認しながら「すべて保存」または確認付きの「すべて破棄…」を使えます。保存の入力不備や競合がある場合は変更を保持し、「設定を確認」から直前の編集ページへ戻れます。未保存変更の再起動後の復元は行いません。

メインウィンドウの位置・サイズ・最大化状態は自動保存し、次回起動時に復元します。最小化中は通常表示の位置・サイズを保持し、「起動時に最小化」の設定も優先します。モニターの取り外しや解像度変更で画面外になる場合は、現在の画面内へ補正します。

- **ホーム**: 実行中・エラーのApplet数、コマンド数、ピン留めしたコマンドとApplet一覧。
- **Applet**: 検索付き一覧から選択。有効・無効、再起動、Appletが提供する画面と操作。横並びの「説明・設定・ショートカット・ログ」タブで、その下の内容を同じページ内で切り替えます。選択中のタブは色で表示し、タブにフォーカスすると左右キー、Home/Endでも切り替えられます。ログは選択したAppletだけを表示し、検索・レベルで絞り込めます。ショートカットは上部の「ショートカット」タブから編集できます。左の「並べ替え」をONにすると、つまみのドラッグ・上下ボタン・つまみにフォーカスして上下キーでApplet順を変更できます。保存すると再起動後も保持され、新規Appletは末尾へ追加されます。リボンの配置やキーの実行順は変わりません。
- **設定**: ホスト設定のカテゴリと全体のショートカット一覧。ショートカットはAppDockを先頭、その下にApplet一覧の順でグループ表示します。個別設定はAppletページに集約しています。Appletの設定項目は検索でき、選択式設定と動的なモニター一覧に対応。
- **ログ**: 直近500件、検索、レベルでの絞り込み。ファイルログは1MBで1世代ローテーション。
- **コマンドパレット**: 既定は `Ctrl+P` / `Ctrl+Shift+P`。`Ctrl+,` で設定を開きます。コマンド名・Applet名・IDで検索し、↑／↓キーで選択、Enterで実行、Escapeで閉じます。☆でピン留め、各行の↑／↓ボタンでピンの順番を変更できます。ピンと順番は操作時に保存します。

Appletページの設定・ショートカットと設定ページの全体ショートカットは同じ編集状態を使います。未保存の編集内容はページを行き来しても保持されます。「変更をすべて保存」は、別Appletやホスト設定・プロフィールを含め、両ページで編集中の変更とAppletの並び順をまとめて保存します。並べ替えモードの「並び順を含む変更を保存」も同じ全体保存です。「変更を破棄して再読み込み」もすべての未保存変更に適用されます。JSON編集中は内容をフォームへ引き継ぎ、不正なJSONは元の入力を保持して修正を案内します。

Applet画面と設定画面の左側の一覧は、同じ背景・余白・選択表示で名前を左揃えに表示します。左パネルの右端をドラッグすると幅を変更でき、両画面で共通の幅を使います。変更した幅は自動保存されて次回起動時も復元します。境界にフォーカスして左右キーでも調整できます。幅は220～480pxで、小さいウィンドウでは表示幅を抑えます。幅はこのPCのLOCALAPPDATA内に保存します。ショートカット設定のコマンド検索と「すべて／割り当て済み／未設定／登録エラー」の切り替えボタンは同じ行に表示します。表示領域が足りない場合は折り返します。

ページ移動は左の「リボン」に集約しています。「設定 → リボン」で標準ボタンと対応Appletのボタンの表示・非表示を選び、上寄せ・下寄せを指定して、それぞれ行をドラッグするか上下ボタンで並べ替えて保存できます。セパレーターも追加・削除・並べ替えできます。初期状態ではテーマとプロフィールが下寄せです。「リボンを初期状態に戻す」も利用できます。設定ボタンを隠した場合はリボンの空き領域を右クリックするか、`Ctrl+,`や「設定を開く」コマンドから設定へ戻れます。

ページを持つAppletは「設定 → 対象Applet」の「表示方法」で、本体のページまたは別ウィンドウを選べます。リボンボタン・開くコマンド・ショートカットは同じ表示方法に従います。画面を表示中に変更して保存すると、そのまま表示先を切り替えます。ページを離れても、常駐処理はAppletを無効化するまで継続します。すべての独自ウィンドウがページ表示に対応するわけではありません。

ビルトインコマンドの「再起動」（`appdock.restart`）と「終了」（`appdock.quit`）は、AppDock本体を再起動・完全終了します。コマンドパレット、ピン留め、ショートカット、トレイ表示・クリックへの割り当てに対応し、既定のキー割り当てはありません。どちらもAppletを停止してから終了し、再起動は保存済みの設定で起動し直します。単一EXE版は元の配布EXEから再起動します。再起動時は「トレイに最小化して起動」の設定にかかわらず画面を表示し、開いていたページ・設定カテゴリ・選択Appletを復元します。通常の起動ではトレイ開始の設定を使います。

設定の「変更をすべて保存」は、表示中のAppletだけでなく、すべてのカテゴリの未保存変更をまとめて保存します。変更したカテゴリ・Applet名には印が付き、ページやAppletを切り替えても編集内容を保持します。保存バーはスクロール中も表示します。「変更を破棄して再読み込み」は全カテゴリの下書きを破棄します。JSONの構文や内容に誤りがある場合、Appletからの直接移動でもJSONを保持し、修正後にフォームへ切り替えられます。

対応Appletの設定ページには操作ボタンも表示します。ボタンは押した時点で実行し、成功・失敗をその近くへ表示します。未保存の設定を保存する操作とは別です。Appletが停止中の操作は利用できません。

通常の単一EXE版にはAppletを同梱していません。初回起動時のApplet一覧は空で、必要なAppletをEXEの隣の `extensions` に追加して使用します。

## オールインワン版

AppDockのGitHub Releaseに添付する`AppDock.at365-all-in-one-<本体の版>.zip`には、単一EXEのAppDock本体と、リリース時に同梱した全Appletが入っています。ZIP全体を新しい書き込み可能なフォルダーへ展開し、`AppDock.at365.exe`を起動してください。AppletはEXEの隣の`extensions`に配置済みなので、使いたいものを一覧から有効にできます。初期状態はすべて無効です。.NET 10 Runtimeなど、本体・各Appletの動作要件は通常版と同じです。

同梱したAppletの版は`bundle.json`で確認できます。このファイルは配布時の一覧で、導入後の個別更新には追従しません。既存環境の更新には、本体・Appletの更新ボタンを利用してください。オールインワンZIPを既存フォルダーへ重ねて展開すると、個別に更新したAppletを古い版へ戻す場合があります。

## ショートカット

「設定 → ショートカット」の一覧表で、コマンド・キーバインド・「いつ・どこで」を設定します。キー欄を選んでキーを押し、「保存」で確定します。「割り当てを追加」で同じコマンドに別のキーや条件を追加でき、行ごとに有効/無効・解除・実行順を変更できます。Escapeで記録終了、Tabで次の欄へ移動します（Ctrl+Tab等は記録できます）。

「いつ・どこで」はリストから選びます。

| 条件 | 受け付ける場面 |
| --- | --- |
| グローバル | 他アプリ操作中やトレイ格納中も有効 |
| AppDock全体 | 本体またはAppDockが管理するAppletウィンドウを操作中 |
| すべてのApplet | いずれかのApplet操作ページがアクティブ |
| Gmailなどの提供元名 | そのコマンドを登録したAppletの操作ページがアクティブ |
| 指定したApplet | チェックしたAppletのどれかの操作ページがアクティブ |

提供元の項目にはApplet名だけを表示します。AppDock本体のコマンドにはこの項目はありません。
新しくキーを割り当てると、Appletのコマンドは提供元のApplet、本体のコマンドはAppDock全体が選ばれます。既存の割り当ての変更や複製では、選んでいた条件を保持します。
ショートカット一覧・コマンド検索・ホームのピン留めには完全なコマンドID（例: `at365.gmail.nextAccount`）を表示します。コマンド名・提供元名・コマンドIDで検索できます。
ショートカットの一覧はマウスジェスチャーと同じ「順番・有効・コマンド・キーバインド・いつ・どこで・その他」の構成です。有効スイッチで切り替え、行頭のつまみをドラッグまたは上下キーで同じApplet内の実行順を変更できます。番号はグループ内の順番です。検索中も元の番号を表示します。「…」から複製・確認付きのキー割り当てクリア・既定へ戻す・全体の実行順を上下へ変更できます。新規追加は「割り当てを追加」でコマンドを選び、キーを指定して保存します。コマンド選択中に操作は実行しません。Tab・Escapeなどは「特殊キーを選択」から指定できます。ショートカットとマウスジェスチャーの「…」列は細く揃えています。

両方の一覧は、すべてのグループで「順番」列と隣の列の位置を揃えています。長いグループ名やコマンド名があっても列幅は変わらず、狭い画面では表の中を横にスクロールできます。

グローバルキーは登録に失敗したときだけ理由と「登録を再試行」を表示します。キー入力中もエラー表示を保ち、正常時の「登録済み／未登録」や「同じキーの割り当てあり」は表示しません。同じキーに複数のコマンドを割り当てることはできます。

割り当てを外すときは「…」→「キーのクリア」を選び、確認後に保存します。無効な割り当てや停止中のAppletでも操作できます。選んだ割り当てだけを解除し、同じコマンドの別の割り当ては残ります。Deleteはキー欄でショートカットとして記録できます。

Appletを新しく導入してAppDockを起動すると、そのAppletが指定した既定のキー・条件・有効状態を初回だけ追加します。Applet詳細の「ショートカット」には、そのAppletの割り当てをまとめて初期値へ戻すボタンがあります。変更は「保存」で確定します。
「設定 → WebApplet」では、これから追加するWebAppletの既定の割り当てを編集できます。初期状態はリロード=F5、戻る=Alt+左、進む=Alt+右で、いずれも追加したWebAppletのページで有効です。変更は既存のWebAppletには遡って反映されません。

Gmail、各WebAppletを個別に選択できます。対象は名前を変更しても保持されます。独立したWPF/WinForms等のnative Applet独自ウィンドウはページ条件の対象外です。

同じキーの複数割り当てを許可し、押した瞬間に条件を満たした利用可能なコマンドを実行順に処理します。同じコマンドが重なった場合は1回だけ実行します。途中でページが変わっても実行対象は変わりません。失敗はログに記録して後続へ進みますが、終了・再起動後の処理は実行されません。実行中のコマンドの再入と長押しによるローカルキー連打は抑制します。

Ctrl / Alt / Shift、Pause、F1〜F24などに対応します。本体の文字入力中はCtrl/Altなしのキーを実行しません。AppletのWeb画面では通常の文字入力を保つため、Ctrl/Alt付き・F1〜F24・Pauseだけを受け付けます。IME変換中のローカル入力、キー記録中は実行しません。グローバルキーはOS登録なので他アプリの入力にも作用します。

「割り当て済み／未設定／登録エラー」で絞り込めます。本体だけ・Applet別の入口も同じ編集データを使います。未導入Appletや現在利用できないコマンドの設定は保持します。トレイ表示はコマンド単位で設定します。

グローバルは利用可能なコマンドのキーをWindowsへ登録します。同じキーは一度だけ登録し、条件判定後に複数コマンドへ振り分けます。他アプリとの競合は登録エラーとして表示し、再試行できます。キー記録中は一時解除し、停止・変更・終了時に更新/解放します。Watchの既定はグローバルのPauseです。

## プロフィール

「設定 → プロフィール」でユーザー名とアバターを変更できます。PNG / JPEG（5MB以下）を選び保存すると、`data/assets/profile/`に元のファイル名で登録します。同名同内容は再利用し、同名の別画像は登録できません。画像を外しても登録ファイルは残します。設定には相対パスだけを保存し、対応表は作りません。

## Appletの追加

### URLからWebAppletを追加する

Applet一覧の「WebApplet」は本体組み込みの管理入口です。「設定」でサイトを追加・編集し、「ショートカット」でこれから追加するサイトの初期割り当てを編集します。登録したサイトはそれぞれの名前でApplet一覧・リボンに表示され、個別の設定やショートカットも編集できます。

Appletページで停止すると、対象Applet（WebAppletやGmailなど）のリボンアイコンを自動で隠します。再開すると元の配置へ戻ります。


「Applet → WebApplet → 設定」またはAppletページ上部の「WebAppletを追加」で、好きなWebページの名前とURLを登録できます。「変更をすべて保存」でApplet一覧とリボンへ追加され、本体ページまたは別ウィンドウで開けます。ページ遷移は開始ページ固定・同じorigin内・HTTP(S)のページを許可から選び、認証先を追加で許可できます。

WebApplet専用のアカウント枠を選び、サイトのログイン状態を保存します。同じ枠を使うWebApplet間で共有し、Gmailのアカウントとは分離します。Web側が推奨設定JSONを提供していれば名前・アイコン・遷移の初期設定を取り込めます。手動の変更は再取得でも保持します。最大64件、アカウント32枠で、追加/削除に本体再起動は不要です。サイトによってはElectron内でログインできない場合があります。

枠の管理は独立した「設定 → Webアカウント」で行います。追加はその場で反映し、名前は入力欄からフォーカスを外すか、「名前を変更」またはEnterで確定します。確定前にEscapeを押すと保存済みの名前へ戻します。「変更をすべて保存」は不要で、WebAppletやほかの設定の下書きを保存しません。「枠を削除」「ログイン情報をクリア」は警告画面で確認してから実行します。使用中の枠は、WebAppletの使用アカウントを変更して保存するまで削除できません。削除は枠と保存データをまとめて消します。使用中などで消せない保存ファイルは削除待ちとして記録し、次回起動時に自動で片づけます。クリアは枠を残してログイン情報とサイトデータを消します。

枠がない状態でWebAppletを追加すると、「個人用」をその場で作成します。WebAppletの下書きを破棄しても枠は残り、管理ページから削除できます。

### 配布フォルダーからAppletを追加する

1. AppDockを完全終了します。
2. 信頼できるAppletの配布フォルダーを、EXEの隣の `extensions` に置きます。`extensions/<Appletフォルダ>/extension.json` と、そのAppletの実行に必要なファイル一式をそろえてください。
3. AppDockを起動し直し、「Applet」一覧で有効にします。新規Appletは既定で無効です。

追加・削除・更新後はAppDockを起動し直してください。同じIDのAppletが複数ある場合は先に見つかったものが使われ、重複をログに記録します。必要なAppDockバージョンは各Appletの案内を確認してください。非対応のバージョンでは起動できないことがあります。

Appletは利用者と同じ権限でファイルやネットワークへアクセスできるため、信頼できるものだけを追加してください。

| Applet | 主な機能 |
| --- | --- |
| [Watch](../Applet.Watch.at365/README.md) | 独立した半透明のデスクトップ時計 |
| [Gmail](../Applet.Gmail.at365/README.md) | 本体ページ／別ウィンドウのGmail画面、新着一覧・検索、アバター、並べ替え・個別監視・通知音（Gmail 0.9.1はAppDock 0.20.0以降） |
| [WallpaperSlideshow](../Applet.WallpaperSlideshow.at365/README.md) | モニターごとの壁紙スライドショーと履歴 |
| [WindowMover](../Applet.WindowMover.at365/README.md) | 最前面ウィンドウの移動・サイズ変更・終了 |
| [WindowsTools](../Applet.WindowsTools.at365/README.md) | 消灯予約・キー送信・無操作時のPCロック |
| [WebBrowserTools](../Applet.WebBrowserTools.at365/README.md) | ブラウザー操作コマンド（ジェスチャーは本体設定） |

Appletは設定された表示名で表示します。表示名・元の名前・IDのいずれでも検索できます。

通知対応のAppletが新着を知らせると、AppDockのトレイに橙色の印を表示します。対応Appletで通知を確認・クリアすると解除されます。トレイのクリック動作やメニュー表示は、従来どおりホスト設定で選択できます。

Windowsのデスクトップ通知をクリックしたときの起動先は、その通知を出した配置先のAppDockです。起動中は対応Appletの操作を実行し、終了後や古い通知では本体を開きます。修正版への更新前に表示された通知には旧版の起動先が残るため、新しく届いた通知から確認してください。

Web画面対応のAppletは、アカウントごとに独立したブラウザー領域を使用します。ログインは表示されたWebサービスの画面で利用者自身が行い、ログイン状態はPC専用の`%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/web-accounts/`へ保存します。Applet更新時もこのフォルダーを保持してください。Gmail画面の×は非表示、Appletの無効化で監視とページを停止します。

## Appletの遅延開始

すべてのAppletに「開始までの秒数」を設定できます。有効化・再起動から指定秒数後にプロセスを起動し、待機中もAppDockの設定は編集できます。0で即時、最大86400秒。無効化・AppDock終了で取り消し、待機中の秒数変更で待ち直します。実行中の変更は次回から適用します。既定の待ち時間はAppletごとに異なり、指定がない場合は即時起動します。開始待ちの詳細画面には予定時刻と「今すぐ開始」が表示されます。

## アップデート

更新が適用された後のお知らせは、画面左下のステータスバーに小さく表示し、約5秒で自然に消えます。×ですぐに閉じることもできます。トレイ開始時はウィンドウを表示してから数秒間お知らせします。失敗した更新の結果は、確認して閉じるまで画面上部に残ります。

「設定 → バージョン情報・更新」の色付きボタンから、本体・Appletの一括更新を行います。本体の更新元や起動時チェックは、普段は閉じている「更新の設定」を開いて変更します。Appletの更新元は、同じ画面の「インストール済みのApplet」にある各欄の「更新元の設定」から変更できます。本体・Appletとも「既定に戻す」を利用でき、変更後は「変更をすべて保存」を押してください。Appletの既定値は配布元が指定した更新先で、空欄の保存は更新確認を無効にします。ローカルの絶対パス、UNC、HTTP(S)の更新情報JSONのURL、`github:owner/repo`、GitHubリポジトリ/リリースのURLに対応します。Webの配布フォルダーURLは末尾に `/` を付けます。本体には `update.json` と本体EXE、Appletには発行済みファイル一式または `update.json` と `update.zip` が必要です。ローカルの既存Applet発行フォルダーは `extension.json` を直接読み取れます。GitHubのReleaseには更新情報とビルド済み配布物を添付します。

- **本体と全Appletを更新**: 本体とインストール済みの全Applet（無効なものも含む）の更新をまとめて準備し、確認後に1回の再起動で適用します。本体の新版を一緒に適用する場合は、その版が必要なAppletも更新できます。更新がない対象や、更新元が未設定・取得できない対象は交換せず、各欄に結果を表示します。WebAppletは本体と一緒に更新されます。
- **AppDockを更新**: 本体EXEを更新します。画面下部からも利用できます。
- **Appletを一括更新**: 無効なAppletも含めて確認し、適用できる更新をまとめて準備します。未設定・通信エラー・必要な本体バージョン不足は各Appletに表示します。
- **このAppletを更新**: 選んだAppletだけを更新します。Appletの詳細画面にもあります。

最終確認の日時は、それぞれの「更新を確認」ボタンの隣に表示します。「すべての更新を確認」の隣には、直近の対象確認日時を表示します。

更新の確認・取得中は画面上部に進行状況を表示します。ダウンロードでは取得量・全体量・割合、一括更新では何件目かを確認できます。完了量が分からないフォルダー取得では、取得済み容量を表示します。「キャンセル」で準備を中止し、インストール済みファイルを変更せず元の操作へ戻れます。交換直前の確認画面では、その画面のキャンセルを使用します。更新開始を確定した後はファイル交換を中断できません。

準備・ハッシュ検証後に対象と版を表示します。「更新して再起動」を押すと本体と全Appletを終了し、共通ミニプログラムが交換して再起動します。一括更新の再起動は1回です。0.22.1以降からの再起動後は、トレイ開始の設定にかかわらず元の画面を表示します。旧版で記録されていない画面状態は復元できません。未保存の設定がある間は更新・確認ボタンを使えません。有効・無効、`settings.json`、`data`内の設定・ログイン情報、ほかのAppletは保持します。対象Appletの配布フォルダーは一式交換するため、独自の保存データはその中へ置かずAppDockの保存領域を利用してください。

起動時の本体/各Appletの更新確認、確認までの待ち時間、更新発見時の通知を設定できます。起動時は情報の確認だけでダウンロード・更新は行いません。起動時確認は既定OFF、待ち時間は10秒です。「同じバージョンの再適用」をONにすると同じ版のビルドし直しも適用できます。古い版へは戻しません。単一EXE形式を維持し、ミニプログラムはEXE内から更新時だけ一時フォルダーへ取り出します。

本体更新は元の名前 `AppDock.at365.exe` のportable版で利用します。信頼できる配布元を指定してください。通信に設定・メール・画像・ログは含めません。ハッシュはファイルの整合性確認で、配布元を保証する電子署名ではありません。非公開GitHubの認証、プレリリースは非対応です。交換完了前の失敗は元の配布物へ復元し、結果を画面とログへ表示します。中断記録がある場合は起動時に復旧を試み、全交換の完了が記録済みなら新しい版を保持して後片付けします。強制終了などで復元エラーが出た場合は、一時ファイルとPC専用保存先の`update-transaction.json`を残して確認してください。

## モニター設定と画像履歴

WallpaperSlideshowの複数ソースフォルダー・表示モード・タイル枚数・上下左右の余白をモニターごとのフォームで編集できます。旧JSON設定も読み取り、フォルダー選択・項目追加・並べ替え・削除に対応します。

履歴画像は指定したサイズで表示します。画像プレビューとパネル上部のモニター切替に対応しています。

## トレイの操作

「設定 → タスクトレイ」でクリック・ダブルクリックと右クリックメニューを編集します。「＋ コマンド」は検索して選択、「＋ グループ」は任意の名前で追加、「＋ 区切り線」は項目の間を区切ります。グループは1段で、別のAppletのコマンドも同じグループへ入れられます。

左端のハンドルをドラッグ、または選択した項目の上下ボタンで並べ替えます。ハンドルにフォーカスして上下キーでも移動できます。「配置先」でトップレベル／グループを選べます。グループ解除は中の項目をその位置へ戻します。「メニューから外す」はトレイへの配置だけを解除します。変更は「変更をすべて保存」で反映し、破棄もできます。

「設定…」「終了」は常に末尾固定です。旧設定は現在のApplet別グループを引き継ぎます。空グループや余分な区切り線は実メニューに表示しません。利用できないコマンドも配置を保持して無効表示します。クリック先が利用できない場合はログに記録してウィンドウを開きます。

0.16.4以降は、同じ場所の単一EXEを更新しても、Windows通知領域のアイコン識別を維持します。今回の変更後は最初に一度だけ、必要ならWindows側でアイコンを常に表示する設定（ピン留め）にしてください。以後は同じEXE名・配置先・Windowsの一時フォルダーで使う限り、更新で新しいアイコンとして登録されることを防ぎます。EXEの移動/改名や一時フォルダーの変更は別の配置として扱います。Windows自身による設定のリセットは防げません。

更新はAppDockを完全終了してから行ってください。実行用ファイルは`%TEMP%/AppDock.at365-<識別子>/`へ展開され、EXEの配置フォルダーの同期には含まれません。二重起動では使用中の本体を再展開せず、既存のAppDockを開きます。一時展開ファイルは最後の本体/ランチャーの終了後に削除します。ランチャーだけが強制終了された場合に残った一時ファイルは、次の通常起動・終了で整理します。共有設定・登録素材はEXE隣、ログインなどのPC専用データは`%LOCALAPPDATA%/at365/AppDock/`配下です。詳細は[保存先](#設定とデータの保存先)を参照してください。

JSONでは`trayMenu`にメニュー構成、`host.trayClickCommand`にクリック先を保存します。`trayCommands`は旧形式の移行用で、新しい構成がある場合は派生値です。空にしたメニューへ項目を自動復活させません。

「タスクトレイ」で「トレイクリックのコマンド」と「トレイダブルクリックのコマンド」を別々に設定できます。クリックの既定は「AppDockを開く」です。ダブルクリックの既定は未設定。未設定の場合は従来どおりシングルクリックを即時実行します。

ダブルクリックに割り当てると、Windowsのマウス設定に応じた判定時間だけシングルクリックを待機させます。判定時間を取得できない場合は、Windowsの既定値500ms（0.5秒）を使用して警告を記録します。ダブルクリックが来れば待機中のシングルを取り消し、ダブル側だけを実行します。保存後すぐ反映し、再起動は不要です。JSONの`host.trayDoubleClickCommand`はコマンドIDまたは`null`（未設定）です。

## ハードウェアアクセラレーション

「一般」の「ハードウェアアクセラレーション」で、AppDockの画面描画にGPUを使用するか切り替えられます。既定はON。変更を保存後、トレイの「終了」でAppDockを完全終了し、起動し直すと反映します。ウィンドウを閉じてトレイへ格納するだけでは反映されません。

「一般」の「スタートアップに登録」をONにして保存すると、このWindowsユーザーのサインイン時にAppDockを起動します。「常に管理者として起動」もONにすると管理者権限で起動します。既定はどちらもOFFで、「トレイから起動」とも組み合わせられます。

管理者設定は管理者グループに所属するWindowsユーザーで使用してください。管理者でのスタートアップ登録・権限変更・解除にはUAC確認が必要です。登録後のサインイン時には毎回のUAC確認を出しません。手動でEXEを開く場合はUAC確認を表示します。キャンセルすると通常権限で動作し、設定画面に結果を表示します。編集中の内容を保存すれば「管理者として再起動」も使えます。管理者設定をOFFにした後は完全終了し、通常の方法で起動し直してください。

登録状態と現在の権限は「現在の起動状態」で確認できます。Windows側の変更後は「状態を確認」を押してください。登録はEXEの配置先とユーザーごとに分かれるため、移動・削除する前に登録をOFFにして保存します。以前の手動登録（スタートアップフォルダー、別名のタスクなど）は自動削除しません。必要なら以前の登録を解除してください。

JSONでは`host.hardwareAcceleration`に`true` / `false`を保存します。項目がない旧設定はONで読み込みます。Applet独自の描画設定は変更しません。

## 設定とデータの保存先

単一EXEの配布方式は維持しています。**共有する設定・登録素材はEXEの隣、PC専用データはLOCALAPPDATA**へ保存します。EXEとextensionsの配置先は従来通りです。

| 保存先 | 内容 |
| --- | --- |
| EXE隣の`settings.json` | 通常の設定・Applet全体設定・キー・リボン・プロフィール |
| `data/web-applets/accounts.json` | 共有するWebApplet枠の名前・ID |
| `data/assets/profile/` | 登録したアバター原画像 |
| `data/assets/applets/<Applet ID>/sounds/` | 登録した通知音（Gmailはat365.gmail） |
| `%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/` | Chromium、全ログイン状態、Gmail専用枠、Window状態、処理データ、秘密情報、ログ、更新記録、設定バックアップ |

Webアカウント枠が空で以前のWebAppletが残っている場合は、設定 → Webアカウントで枠を追加し、WebAppletの設定でその枠を選んで保存できます。ホスト画面の操作エラーはログページにも記録します。

配置IDはEXEの配置先から決まります。同じ場所で更新するとPC専用データを引き継ぎ、配置を変えると新しい保存先になります。WebApplet枠は同期できますが、ログインは各PCで行います。Gmailの枠は名前・ID・枠ごとの監視や通知音の割り当ても含めPC専用です。

**旧.appdockのPC専用データは自動移行・削除しません。** 旧データが残る場合は画面に案内します。同期前に完全終了して旧データを整理してください。新方式では旧ログインやGmail枠を引き継がず、各PCで登録し直します。新しく登録した共有素材・枠を使い始めた後はdata全体を消すとそれらも消えるので、旧PC専用部分だけを整理してください。

ファイル同期で届いたsettings.jsonは起動中に自動反映します。書き込みが落ち着くまで待ち、変更通知に加えて2秒ごとの照合も行います。壊れたJSONや一時的な欠落では最後の正常な設定を使い、編集中の入力を保持して古い内容での上書きを拒否します。ハードウェアアクセラレーションなど起動時だけ使う設定は次の起動で反映します。Windowsの起動登録はこのPCでの明示保存が必要です。

正常な設定を各PCの`settings-backups/`に直近20世代とlast-good.jsonで保存します。破損したまま再起動してもバックアップがあれば動作を続け、共有ファイルを勝手に書き戻しません。「バックアップで復元」は同期先にも届くことを確認してから実行し、破損ファイルをPC内へ退避します。正常な設定が届けば通常動作へ戻ります。バックアップをまだ作れていない場合は読み込みエラーになります。

登録素材のファイル名をIDとして使います。同じ登録元・用途のフォルダー内で同名別内容は拒否し、別フォルダーでは同名を使えます。素材一覧は実ファイルから作り、枠を消しても共有素材を自動削除しません。素材だけ届く変更も表示に反映します。

2台で未同期のまま同時に保存した変更を自動合成する仕組みではありません。同名別素材を2台で同時登録する場合も同期サービスの競合になるため、競合コピーやPC内の設定バックアップから内容を確認してください。同期サービスの設定は利用者が行います。

JSONはUTF-8の標準JSONです。JSONCには対応しません。旧settings.jsonの欠落項目は既定値で補います。`profile.avatar`は登録画像の相対パスまたはnullで、従来のavatar.pngも読み取れます。[設定例](settings.example.json)を参照してください。
