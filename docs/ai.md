# AI文章生成と共通API

AppDock 0.37.0以上で利用できる。OpenAI互換Chat Completionsを使い、単発の文章を生成する。本体は接続先・認証・共通プロンプトを管理し、AppletとMCPはモデル・追加プロンプト・入力を指定する。Gmail固有の設定と通知連携は別工程で、今回の本体実装には含まれない。

接続ごとの出力上限・待ち時間と共通エラー通知は0.39.0以上で利用できる。

エラー通知はバナーを必須とする。通知全体のOFFは設けず、表示時間や追加の通知先・読み上げを変更できる。

## 設定と利用

「設定 → AI」で接続を追加し、名前・ベースURL・任意の既定モデル・認証方式を設定する。Ollamaは`http://<サーバー>:11434/v1`、LM Studioは`http://<サーバー>:1234/v1`、OpenAIは`https://api.openai.com/v1`が入口になる。llama.cppや他の互換サーバーは利用するサーバーのホスト・ポートとAPIルートを指定する。

接続一覧の＋で追加、各行の歯車で編集する。同じ共通ダイアログに種類・URL・名前・認証・モデルを表示し、互換性の詳細設定は折りたたむ。URLまたはAPIキーのEnter、モデル欄の取得ボタンで、保存前の入力からモデル一覧を取得できる。IME変換確定のEnterでは取得しない。URLの補正はEnterかblurの時だけ行い、blurでは通信しない。

ダイアログ入力と一覧取得ではsettings.jsonやAPIキーの保存ファイルを変更しない。OKで接続情報をまとめて保存し、キャンセル・Escape・画面の終了では破棄する。APIキーはOKの時にこのPCへ暗号化保存する。登録した接続は常に有効で、接続ごとのPC利用スイッチは設けない。AppletとMCPからの利用は、さらに「設定 → 操作の許可」の各列で「AI文章生成」と必要な前提操作を許可する。モデル一覧には情報取得、文章生成には情報取得・コマンド実行の許可が必要。

接続は8件まで登録でき、IDは名前変更でも保つ。共通の既定接続が未設定なら、呼出しで接続IDを指定する。ゴミ箱から確認して削除すると、このPCの対応キーも削除する。既定接続を削除した場合は既定を解除する。参照先が見つからなかった場合に別接続へ切り替えることはない。一覧の並べ替えボタンはドラッグ・上下ボタン・Alt＋↑↓に対応するダイアログを開き、OKで表示順を保存する。表示順を生成優先度として扱わない。

共通プロンプトと既定接続は従来どおり即時保存する。接続の編集・削除は開いた時点の接続とキーの改訂を検査し、競合時は入力を残して開き直しを案内する。並べ替えは接続IDの集合と元順序を検査し、別接続の名前などの新しい値を保持する。全体の保存／破棄状態は持たない。

共通プロンプトは全用途の基本方針、追加プロンプトは今回の用途の指示、入力は処理するテキストまたはJSONとする。追加プロンプトは共通プロンプトを置換しない。共通方針を優先するよう指示を合成するが、モデルが必ず指示を守る保証ではない。モデルの明示指定がなければ接続の既定モデルを使い、両方なければエラーにする。呼出しで共有設定を書き換えることはない。

## モデルによる互換性の差

出力上限の形式は、ローカル互換APIでは通常`max_tokens`、OpenAIでは`max_completion_tokens`を選ぶ。Temperatureと推論の強さは対応するモデルでだけ明示指定する。OpenAIでは`store:false`を指定できるが、提供元の監査・不正利用対策ログまで非保存にするものではない。HTTPのリダイレクト・パラメーターの自動変更・失敗後の自動生成・クラウドへの自動切替は行わない。

推論を行うモデルでは、トークン上限が思考に使われて本文が空になる場合がある。上限終了や空本文は失敗として返す。短い通知文等では、対応が確認できる場合に推論の強さへ`none`を指定する。モデル名から推論設定を自動判定しない。実測結果とモデル条件は[検証記録](../VERIFICATION.md)を参照する。

「設定 → AI → 対象サーバーの歯車 → サーバーに合わせた詳細設定」で、既定の出力トークン上限と待ち時間を設定する。初期値は8,192トークン・60秒で、設定がない既存接続もこの値を使う。入力中は保存せず、他の接続情報と一緒にOKで保存する。出力上限は32〜131,072、待ち時間は1〜600秒の整数。上限なしは設けない。

APIの`maxOutputTokens`／`timeoutMs`を明示した場合は、今回の要求だけその値を優先する。未指定の項目は選択した接続の既定値を使い、試験画面も同じ経路を使う。トークン上限はAppDockが要求へ渡す最大値で、その量を毎回生成する指定ではない。モデル／サーバー固有の上限を超える場合はサーバーが拒否することがあり、自動で値を変更して再試行しない。

思考も出力上限の枠を使うモデルがある。OpenAIの`max_completion_tokens`も可視出力と推論トークンを含む上限である。[公式API仕様](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。大きな値では計算時間やクラウド料金が増える場合があるため、用途に必要な範囲へ設定する。本文4,096コードポイント、応答1MiB等の制限は独立して適用し、長文出力を無制限に受け取る機能とはしない。

サーバーが`finish_reason:length`を返した場合は`AI_OUTPUT_LIMIT`と「出力トークンの上限に達したため、文章を最後まで生成できませんでした」を返す。空本文やそれ以外の不正な応答と区別し、上限または推論の強さの調整を案内する。受付済みジョブの失敗は、試験画面・Applet・MCPとも[共通のエラー通知とログ](error-reporting.md)へ一度だけ出す。「設定 → 通知 → AppDock → エラー通知」で通知先等を変更でき、エラーログにも記録する。取消はエラー通知にしない。

思考で上限に達するモデルでは、「設定 → AI → 対象サーバーの歯車 → サーバーに合わせた詳細設定 → 推論の強さ」に`none`を入力してOKで保存し、再試験する。これは対応しているモデルで思考を無効にする指定で、上限自体を増やす操作ではない。空欄は省略を意味し、思考の無効化を保証しない。サーバー／モデルがこの指定を受け付けることを確認し、未対応のモデルへ一律に設定しない。

モデル一覧の非対応は手入力で対応できる。一覧にあることは文章生成への対応やロード済みであることを意味しない。AppDockはモデルのダウンロード・起動・常駐設定を管理しない。

## 共通API

同じ[AppDockApi](appdock-api.md)と操作カタログを使用する。Appletには`appdock-api` capabilityが必要。モデル・追加プロンプトを指定できるが、URL・APIキー・HTTPヘッダーを引数で上書きできない。

| 操作               | MCPツール                  | 入力                                                                                   |
| ------------------ | -------------------------- | -------------------------------------------------------------------------------------- |
| `ai.text.generate` | `appdock_ai_generate_text` | 必須requestId、任意connectionId/model/additionalPrompt/input/timeoutMs/maxOutputTokens |
| `ai.jobs.get`      | `appdock_ai_get_job`       | jobId                                                                                  |
| `ai.jobs.cancel`   | `appdock_ai_cancel_job`    | jobId                                                                                  |
| `ai.models.list`   | `appdock_ai_list_models`   | 任意connectionId                                                                       |

生成の受付はjobIdと`completion:accepted`を返す。状態は`queued/running/completed/failed/canceled`。完了時だけtextと任意usageを取得できる。エラーは安全なcode/message、状態にはモデルと接続ID・時刻を含める。本文が期限で回収された後は`resultExpired:true`となり、再生成しない。

Nodeの例:

```ts
const accepted = await context.appdock.call('ai.text.generate', {
  requestId: crypto.randomUUID(),
  model: 'configured-model-id',
  additionalPrompt: '入力を短い文章に整えてください。',
  input: '処理が完了しました。',
});
const job = await context.appdock.call('ai.jobs.get', { jobId: accepted.jobId });
// queued/runningの間は間隔を置いて取得し、completedのtextを利用する。
```

.NETは既存`context.AppDock.CallAsync`を使い、同じ引数を匿名型等で渡す。生成完了までRPCを待たせず、短い受付操作と状態取得へ分離する。取消はjobIdを`ai.jobs.cancel`へ渡す。SDKの新しいプロパティや別のHTTPクライアントは必要ない。

所有者は本体が決定する。AppletはIDと起動世代、MCPは共通認証域とAI許可の世代に束縛する。他のAppletのジョブを取得・取消できない。共通MCPトークンを使うクライアント同士は同じ認証域になる。

## 期限と上限

- 接続あたり同時1件、全体2件。受付済みは全体16件・所有者4件まで。
- 接続あたり毎分30件、バースト3件。超過は`AI_RATE_LIMITED`。課金額の上限保証ではない。
- 共通/追加プロンプトは各2048コードポイント、入力8192、モデル200、HTTP要求64KiB、応答1MiB、結果本文4096コードポイントまで。
- 生成期限は受付から待機・HTTP・検証まで。接続の初期値60秒、APIは`timeoutMs:1000〜600000`を指定できる。出力上限は接続の初期値8,192、APIは`maxOutputTokens:32〜131072`。両方ともAPIで明示した値を優先する。
- 同じ所有者とrequestIdの同じ引数は保持期間中の元ジョブを返す。異なる引数は`AI_REQUEST_CONFLICT`。プロパティ順や省略した空の入力・追加プロンプトは正規化する。
- 終端メタデータは最大512件・30分。生成本文は最大64件・60秒のメモリー保持。タイマーで本文を解放し、ディスクへ保存しない。
- モデル一覧は5秒・1MiB・1000件まで。同じ所有者・接続の同時取得はまとめる。

共有設定・キー変更、接続削除、Applet停止・世代変更、MCP無効化・認証更新・AI許可取消、ホスト終了で対応する処理を取り消す。APIキーの変更は当該接続に限定する。古い条件の遅い応答は採用しない。取消は通信を中断するが、サーバー内の計算・課金の停止までは保証しない。

## 保存とデータ送信

通常設定は共有settings.jsonのai。APIキーはPC専用rootのai-keys.jsonへsafeStorage暗号化で保存し、接続IDと正規化URLに紐付ける。接続ごとの許可ファイルは使用しない。旧ai-access.jsonは参照・更新せず、手元に残っていても動作に影響しない。Applet/MCPのuseAiは各操作許可のファイルに独立保存し、初期OFF、旧設定の省略値も拒否する。

APIキーは正規化URLが一致する場合だけ使う。URL変更後はキーを再入力する。認証なしに変更すると保存時にキーを削除する。OKではSettingsStoreの関連データトランザクションを使い、設定の書き込み失敗時はキーを元に戻す。モデル一覧の一時キーを保存・ログ・画面モデルへ載せない。取得は5秒で終了し、閉じたダイアログの取消が新しい要求を取り消さないよう要求IDで分離する。

キーを画面モデル・部分JSON・エクスポートへ戻さない。プロンプト・入力・生成本文・生のサーバーエラーをログへ含めない。共通プロンプト自体は通常設定として同期するので、秘密値を記入しない。HTTPを使うLAN接続ではTLS暗号化がない。ローカルURLでもクラウドモデルやプロキシが外部へ転送する場合がある。

UIの試験結果はテキストとして表示する。結果をコマンドやHTMLとして実行しない。[設定同期](settings-sync.md)の保存分類と原子的保存を使用し、TTSの設定・キー・許可を共有しない。
