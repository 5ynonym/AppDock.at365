# 通知基盤の設計

## 現在の実装

0.33.0で段階1〜5と設定の即時保存への移行を完了した。通知サービス、種類別の設定、通知センター、バナー、独自デスクトップ通知、Windows通知を共用する。最初の発行元だった未保存警告は、即時保存への移行に伴い削除した。通知基盤は設定の編集状態に依存しない。

| 段階 | 実装結果 |
| --- | --- |
| 1 | 通知サービス、操作、履歴、複数バナーとDefault Shell |
| 2 | 本体・Appletの通知種類と種類別設定 |
| 3 | 通知センターと更新適用結果のバナー |

## 構成と責務

発行元は種類と内容・操作を指定する。NotificationServiceが通知ID、所有者、集約、状態、期限、操作の排他と履歴を管理する。表示先のadapterは配送と表示だけを担当し、通知の解消条件や寿命を独自管理しない。ShellのControllerとネイティブViewの寿命を分離する。

NotificationSurfaceHostはバナーと独自デスクトップ通知で同じ公開モデルとpreloadを使う。本体からDefault ShellのReact部品をimportしない。追加Shellが未対応・停止・故障した領域は、保存したShell選択を変更せずDefault Shellへ戻す。通知センターもpage.notificationsの公開契約を使う。

具体的な公開型、制限、SDKと旧APIの互換性は[通知契約](notifications.md)、表示基盤は[Shell基盤](shell-foundation.md)と[Shellページ](shell-pages.md)を参照する。

## 通知種類と設定

本体・Appletが安定したtypeId、名前、説明、既定レベル、許可する表示先、既定の寿命、無効化可否を宣言する。Appletの所有者と起動世代は本体が決定し、別所有者の通知や操作を偽装できない。Applet自身の宣言だけで必須通知にはできない。必須通知は理由とrequiredTargetを必要とする。

設定ページの「通知」は導入済み・停止中のAppletも含む種類を一覧表示する。オン・オフ、複数の通知先、表示時間を変更できる。targets:[]は通知センターのみ。時間の空欄は明示的manual、有限秒数はtimed、発行元の条件で終わるconditionには時間を設定できない。必須種類の無効化や必須表示先の解除は拒否する。

notificationPreferences.overridesをsettings.jsonへ保存する。ownerKind/ownerId/typeIdの組で識別し、省略項目は種類の既定値を継承する。未導入・削除済み種類の上書きを受信しても保持する。Applet通知の親スイッチhost.notificationsは維持する。入力途中や保存失敗値は配送方針へ適用せず、正常保存・外部受信した値だけを使う。設定変更はアクティブ通知にも反映し、終了済み履歴や期限切れ通知を復活させない。

## 状態、操作と履歴

info/warning/errorのレベルと、manual/timed/conditionの寿命を扱う。同時に複数の通知を保持し、owner/typeId/dedupeKeyの範囲で集約する。所有者の受付上限は種類別ではなくApplet全体で共有する。

既読、配送成功、画面が閉じたこと、業務上のresolvedは独立した状態である。操作は本体の所有者・世代・通知ID・公開操作IDを照合し、同じ操作の多重実行を防ぐ。失敗しても通知を自動解消せず、通知更新・終了・世代交代後の古いcallbackは無効とする。

persistent履歴はPC専用notifications/history.jsonへ、安全な要約とID・所有者・種類・レベル・時刻・状態・既読・表示先・配送結果を保存する。callback、操作ID、認証情報、生の例外、設定値を永続化しない。sessionは起動中、noneはアクティブ中だけ保持する。終了済みメモリー記録は上限を設ける。既読と削除は書き込み成功時だけ確定し、失敗時は直前の状態を維持する。

## バナー表示

通知ごとにバナーを選択でき、複数通知を縦に積む。内容はテーマと画面サイズに追従し、スクロール・アクション・閉じる操作を備える。本体本文を押し下げない。タイトルバーから通知へフォーカスし、Escapeで元の画面へ戻れる。表示領域の切り替えで通知の業務状態を変更しない。

## 段階3: 通知センター

リボンからアクティブ通知と終了履歴を閲覧する。検索、状態・種類の絞り込み、既読、履歴削除と50件単位の取得に対応する。開いただけで全件既読にはしない。検索の遅い応答や古い操作IDを無効化し、永続化失敗を画面に表示する。詳細や操作は現在有効な通知に限り、履歴へ実行可能なcallbackを保存しない。

更新適用結果はhost/updates/appliedとして、既定banner・6秒で表示する。通知の設定で無効化・表示先・時間を変更できる。update-result.jsonのbytesのhashをPC専用notifications/update-receipt.jsonへ記録し、抑制された場合も同じ結果を通常起動ごとに再通知しない。受付済み記録が失敗した場合は次回の受付余地を残す。

## 独自デスクトップ通知

Windows通知とは別の、トレイ付近の非アクティブWindowに通知を積む。必要なときだけ起動し、本体が非表示でも使える。DIP・作業領域・テーマへ追従し、期限と通知状態は共通サービスが所有する。ロック・全画面等では表示を抑制し、その間も期限は進む。InputHostの照会workerを使い、通知表示のためにグローバル入力hookを追加しない。通知センターへ移動でき、無通知時にViewを解放する。

## Windows通知と互換経路

Windows adapterは起動準備後に有効となる。通知IDからTag/Groupを作り、同じ通知の内容更新は同じOS履歴項目を置き換える。既読や操作中の表示更新だけで再通知しない。OSのcloseや配送成功をresolved扱いにしない。Windowsのポップアップ表示時間・表示可否はOSが管理し、共通寿命の間は通知センターで確認・操作できる。通知の終了・所有者停止では該当OS項目を撤去する。終了時にはcallbackを解放し、OS履歴の残存とは区別する。

ポータブル単一EXEの起動引数・profileを照合する専用URIで通知センターや所有者の許可されたコマンドへ接続する。ランダムcallbackを使い、世代・所有者・終了後の操作を拒否する。旧API通知は本体生成の予約typeId appdock.legacyへ集約し、「旧方式の通知」として設定できる。従来のsilent・クリックコマンド・nullと親スイッチの挙動を保持し、Appletによる予約種類の宣言を拒否する。更新のお知らせはhost/updates/available、既定Windows・manual・silentとして共通基盤へ移した。

## 設定の即時保存と削除した構造

SettingsStoreの保存済み値を正本とし、SettingsInputSessionはページ・モード・操作受付だけを調整する。共有ドラフト、dirty、全体保存/破棄、SettingsNotificationSource、未保存通知種類、途中入力・画像の本体バッファ、専用IPCとURLを削除した。現在のUIだけが不完全入力と保存失敗値を保持し、修正後に再送する。詳細は[設定基盤](settings-foundation.md)。

page.settingsはschemaVersion:2、対応追加ShellはminimumHostVersion:0.33.0以上を宣言する。旧Shellの設定領域だけDefault Shellへ戻し、ほかの対応領域は利用を続ける。保存ファイルと通知SDKの互換性を維持する。

## 検証と環境

型検査、通知と設定の標準回帰、隔離GUI、Node/.NETの発行元、固定単一EXEによる操作・再起動・OS履歴を検証する。正確な件数・固定成果物・限界は[検証記録](../VERIFICATION.md)を参照する。実Google認証や物理的なWindows通知クリックは自動試験と区別する。

A:\\30.PROJECTの開発ドライブへのフォルダマウント変更では、更新helperが登録済み祖先volumeをリンクとして拒否した。検証境界より上の登録済みvolumeだけを許可し、対象・payload内部のリンクや通常junctionを拒否するよう修正済み。隔離EXEの実更新・再起動と完了バナーで確認した。

フォルダマウントへドライブ文字を追加/解除してNodeの実体パスが変わる場合は、固定lockfileでpnpmのworkspace状態を復旧する。実行中にパスが変わった発行は変更後の環境でビルドからやり直す。手順は[開発ガイド](../DEVELOPMENT.md)、実測はVERIFICATIONを参照する。

## 次回以降の範囲

今回の依頼範囲に未実装の段階はない。新しい発行元や表示先を追加する場合も、種類宣言・方針解決・状態・履歴を共用し、設定の未保存管理を再導入しない。履歴の高度な整理、OS固有の追加操作、追加Shellのschema 2移行は必要になった時点で別途設計する。
