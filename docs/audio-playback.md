# 共通音声再生API

## 目的と境界

AppDockが鳴らす読み上げ、Appletの通知音、設定画面の試聴を、一つのFIFOキューで再生する。今後追加する音声再生もこのAPIを基本とし、機能ごとのBrowserWindow/Audio/システムビープや別キューを作らない。Webサイト自身や別アプリ、Windowsが独自に鳴らす音は制御対象外。独自通知音を使う種類指定通知では`silent: true`を指定し、Windows通知の音を重ねない。

本体0.42.0で実装。TTS生成と再生を分離し、音声が準備できて再生キューへ入った順に処理する。生成中は再生枠を予約しない。TTS同士の生成は従来どおり直列で、前のTTSの再生終了後に次の生成へ進む。通知音や試聴はその間にも受付できる。

## APIと責務

- 本体内部は`src/main/core/audio-service.ts`の単一`audioPlayback.play(request)`を使う。受付時に待ち行列へ登録し、戻り値のPromiseは再生・取消・回収の完了を表す。
- 入力は検証済みWAVの`bytes`、任意の`signal`、`speed`、開始直前の`beforePlay`、必須の`playbackTimeoutMs`。秘密・接続先・本文を渡さない。呼出元はファイルの権限・サイズ・形式と所有者寿命を検証する。
- `AudioPlaybackQueue`は順番、待機の取消、容量、待ち時間、終了を管理する。`audio-player.ts`だけがsandbox/contextIsolation付きの一時プレイヤーを作る。前のプレイヤーの回収が終わるまで次を開始しない。
- Applet通知音は`NotificationSounds`でロック・サスペンド中の受付を最大32件保留し、解除後に共通音声キューへ渡す。ファイル読取・再生開始前の再ロックも保留し、開始済みの通知音は停止して再生し直さない。発行元が停止した待機音は捨てる。詳細は[ロック中の保留](notifications.md#ロック中の保留)を参照する。
- Node Appletは既存の`context.audio.play(file)`を入口とする。自身の登録素材ファイル名、または既存契約のローカルWAV絶対パスを受け付け、受付後すぐ戻る。音声バイトをApplet RPCへ返さない。`audio` capabilityを維持する。
- TTSは既存の`tts.speak/jobs.get/stop`と`useTts`許可を維持し、内部再生だけを共通化する。汎用音声のためにTTS接続や権限を要求しない。MCPへの任意ファイル再生の公開は今回の範囲外。

## 制限と取消

共通キューは再生中を含め48件、待機は10分。満杯・期限切れ・再生失敗は呼出元へ失敗を返し、自動再送しない。一件の失敗は次の再生を妨げない。全体終了は受付を閉じ、待機を破棄し、再生中を中断して回収を待つ。

通知音は従来の32件・16MiB WAV・プレイヤー開始から30秒の上限を保つ。読み込み中、待機中、再生中にAppletの稼働世代や試聴対象が失効したら取り消す。WAV未指定・空文字・省略は無音の成功となる。ビープへの代替は行わず、未登録・不正WAVの失敗もビープへ置き換えない。

TTS状態は`queued → generating → waitingPlayback → playing → completed`。失敗・取消は各段階から遷移できる。`waitingPlayback`中は音声を受信済みでもまだ再生しておらず、設定変更・権限取消・通知の開始期限を適用する。`playing`と開始期限の解除はプレイヤーの開始直前に行う。通知の60秒開始期限は生成と共通キューの待機を含み、開始済み再生は自然期限で切らない。

## Gmailの移行

Gmail 0.11.0は`notificationTypes`に`new-mail`（新着メール）を宣言し、旧`notifications.show`から`publish/end`へ移行する。最低ホスト版は0.42.0。既定はWindows通知、10秒、永続履歴。表示先・時間・読み上げはホストの共通通知設定で解決し、読み上げの既定OFFを維持する。

既存のGmailの`notifications`設定は発行スイッチとして保持し、過去のOFFを勝手にONへ移行しない。通知音のアカウント別ON/OFFは従来どおり独立。`notificationDetails`は表示・読み上げ本文だけに適用し、永続履歴はアカウント名・送信元・件名を含まない汎用要約にする。本文は基盤の上限に収める。

アカウントごとに直近の通知IDを保持する。次の新着では前の通知をwithdrawnとして終了し、新しいIDで発行する（新しいイベントの読み上げを失わない）。既読化で新着がなくなった場合と新着表示クリアはresolved、アカウント削除・監視OFF/リセット・発行OFFはwithdrawn。自然期限切れや利用者による終了後のend失敗は再発行しない。Applet停止・再起動時の終了と操作失効はホストの世代管理が担う。

通知音の未選択は無音として既存の空文字設定をそのまま読む。UIは「未選択（無音）」「選択を解除」とし、WAV未選択の試聴は無効にする。素材や共有設定を一括書換えしない。

## 検証

混在FIFO、待機取消、再生中取消と回収、失敗後の継続、容量・待機上限、生成中の通知音、再生待ち中の通知開始期限を回帰試験する。実Electronと固定発行EXEで同時プレイヤー数・順序・終了を確認し、Gmailの設定UIと種類指定通知・操作・安全な履歴を検証する。実Google受信とスピーカーから聞こえる音はfixture成功と区別する。実測はVERIFICATION.mdへ記録する。
