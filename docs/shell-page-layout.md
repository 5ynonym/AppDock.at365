# Shellページの表示領域とレイアウト設計

2026-10-12実装。本文領域の割り当てとShell内部のレイアウトを定義する。検証結果は[VERIFICATION](../VERIFICATION.md)を参照。

## 目的

ホーム・全体ログ・設定へ差し込むShellページに、ホストの本文領域全体を渡す。余白、カード配置、スクロールはShellがページごとに管理する。Default Shellと追加のShell Appletに同じ表示契約を適用する。

「全体」はリボン・ステータスバー・ホストのエラー通知を除いた利用可能領域を指す。Applet詳細内では、詳細見出し・操作・タブを除くタブ本文領域を指す。本文の背景とViewは領域を満たし、文字やボタンには読みやすい内側余白を設ける。

## 変更前の問題

- `src/shared/settings-ui/controls.css` の `.page-content` が `max-width: 1170px` と `margin: auto` を持つ。後段の定義による通常余白は上下26px・左右30pxで、狭い画面では上下22px・左右20pxになる。
- ホーム・全体ログ・設定の `ShellPageSlot` はこの内側に置かれる。設定の `.settings-main > .page-content` も最大幅制限を解除していない。
- `src/renderer/ShellPageSlot.tsx` は `main.bottom - slot.top - 36` から高さを決め、最低140pxを要求する。親から渡された領域ではなく、main全体と固定の控除量に依存している。
- `shells/default/home.css` と `logs.css` はページ余白が `0 2px 12px` で、ホストの余白を前提としている。ホームのAppletカードは通常2列固定。
- 設定Shellは独自の左インデックスと右本文を持ち、右本文にはさらに20pxの余白がある。ログとApplet詳細の一部は親にもスクロールがあるため、単純な拡大ではスクロールや切り抜きが不整合になる可能性がある。
- 通常Appletページには既に `.applet-page-main` による最大幅・外余白の解除がある。同じ考え方をShellページにも適用できる。

## ホスト側の設計

### 全体ページ

ホーム・全体ログ・設定を対象とするレイアウトクラスを付ける。対象の `main` と `.page-content` を縦方向のflex配置にし、`min-width: 0` / `min-height: 0` を連続した親子へ設定する。

- `.page-content` の最大幅制限・中央寄せ・paddingを対象ページに限って解除する。
- エラーバナーなどのホストUIは上部の通常フローに残し、残りの高さをページ枠へ割り当てる。バナーは縮小させず、ページViewが覆わないようにする。
- ページ枠の背景はリボン側から右端まで、利用可能な上端からステータスバー直前まで広がる。
- 本体側はShell本文をスクロールしない。`[hidden]` の設定ページがflex指定で再表示されないよう、セレクターを限定する。
- 共通 `.page-content` 全体の変更は避け、通常Appletページや本体描画の画面への波及を抑える。ホスト配置用CSSは `src/renderer/style.css` に置き、設定Shellもimportする共通コントロールCSSへ不要なホスト指定を広げない。

### 表示枠の寸法報告

`ShellPageSlot` はCSSが割り当てた枠を測定・報告する部品にする。

1. JSで高さを上書きする処理と固定36px控除を除去する。Shell本文枠の最低140px制約も解除する。
2. Slot自身と必要な配置コンテナの寸法を監視し、実際の矩形を取得する。バナーの表示・非表示や折り返し、詳細見出し・タブの高さ変更による位置変化も再報告する。
3. Slot矩形と割当領域・ホスト表示範囲との交差を報告する。幅か高さが0以下、非表示、画面外ならnullを送り、古いViewを残さない。
4. 座標報告は必要に応じてrequestAnimationFrameで集約し、同じ矩形の連続IPCを抑える。解放時は予約処理と監視を回収する。
5. main側のzoom変換、ready待ち、前面順序、フォーカス移動、旧routeの拒否、故障復旧を維持する。寸法通知のためにControllerやViewを再作成しない。

`ShellPageHost` へページ固有のpaddingやDefault Shell判定を加えない。既存のviewport契約内で対応する方針とする。

### Applet詳細への埋め込み

全体ページ用のクラスを詳細画面全体へ流用しない。詳細見出し・タブ等の既存配置を保ち、その下の `.detail-logs` / 設定用 `.applet-settings-panel` からSlotまでをflexでつなぐ。Shellを持つパネルの外側スクロールを解除し、タブ本文の残り全域をSlotへ渡す。

WebApplet管理の設定とショートカット等、本体が描画するパネルのスクロールは独立させる。タブを切り替えた際の非表示・破棄も現行どおりとする。

## Default Shell側の設計

| ページ | 表示・余白 | スクロール |
| --- | --- | --- |
| ホーム | View全体を背景で満たす。ページ内余白は通常24px、View幅600px以下では16px。カードは最小幅約280pxを目安に利用可能幅に応じて1列・2列・3列以上へ増減する。統計カードは幅不足で折り返す | ページ内の1領域でスクロール。内容が少なくてもページ背景は全高を満たす |
| 全体ログ | ページ内に通常24px、狭い幅では16px。見出し・フィルターを上部、件数等の説明を下部、ログ表を残りの高さへ配置する | ログ表だけをスクロールし、列見出しを表内の上端に維持。フィルターは折り返す |
| 設定 | 左インデックスをページ左端・上端・下端へ接続する。右本文の既存20px余白を基本とし、外側余白との二重化を解消する。入力欄の個別の適正幅は維持する | 左インデックスと右本文がそれぞれスクロール。保存操作・フォーム/JSON切替は固定領域に置く |
| 詳細内の設定・ログ | 親のタブ本文が持つ余白を使い、全体ページ用の外周paddingを二重に追加しない。ログは既存scope、設定は既存contextで区別する | 各Shell本文の内側でスクロールし、詳細画面との二重スクロールをなくす |

各Shellの `html/body/#root` とページルートで高さとoverflowの責任を明示する。ログ・設定の固定部分だけで高さを使い切る極端に低い表示領域では、ページ内の単一スクロールへ切り替えて操作を到達可能にする。

レスポンシブ判定は原則として差し込まれたViewの実幅を使う。設定の既存 `hostWidth` は契約の意味を変えずに維持し、折り返し・左幅上限はローカルの実幅でも制約する。保存済みの左幅は狭い表示のためだけに書き換えない。

## 実装の配置

1. `src/renderer/main.tsx` / `style.css`: 全体ページ用レイアウトと詳細内のShellパネルを区別し、枠へ利用可能領域を割り当てる。
2. `src/renderer/ShellPageSlot.tsx` / `AppletSettingsPanel.tsx`: CSS主体の寸法報告と埋め込み枠を整える。
3. `shells/default/home.css` / `home.tsx`: 内側余白、全高背景、カードの可変列を調整する。
4. `shells/default/logs.css` / `logs.tsx`: 残り高さを使う表、スクロール、全体/詳細の余白を調整する。
5. `shells/default/settings.css` / 必要なら`settings.tsx`: 全高の左右領域、実幅に応じた配置、固定操作部と本文の分担を確認する。
6. 関連GUI試験へ境界とスクロールの検証を追加し、現行仕様文書と検証記録を更新する。

表示モデル・操作・設定保存形式は変更しない。既存Shell Appletにも新しい枠寸法が適用されるため、部分差し替えfixtureを使って互換性を確認する。

## 完了条件と検証

- 通常幅・最大化・狭幅・低い高さ、ライト/ダーク、拡大縮小でホーム・全体ログ・設定を確認する。
- 全体ページのSlotが割当領域の四辺に一致し、Shell Viewの実boundsがzoom換算後に丸め誤差1px以内で一致する。SlotとViewの一致だけでなく、Slotと本文の利用可能領域の一致も検証する。
- ホストバナーの出現・消失・複数行化でViewが追随し、リボン・ステータスバー・通知・オーバーレイへ重ならない。
- 長いログ・検索結果・設定フォーム・JSONで、意図した領域だけがスクロールする。最終項目まで操作でき、不要な横スクロールを生じない。
- 詳細内の設定・ログ、WebApplet管理のログ、本体描画の説明・ショートカット・Web設定を切り替えて境界とスクロールを確認する。
- 設定検索からの項目移動、未保存draft、不正JSON、保存操作、Tab/Shift+Tab、テーマ切替を維持する。
- 追加Shellへの部分差し替え、Default Shellへの復旧、safe起動、通常Appletページへの遷移を確認する。

既存 `scripts/shell-home-ui-test.cjs`、`shell-page-ui-test.cjs`、`settings-shell-ui-test.cjs` を中心に変更関連試験を選び、固定単一EXEでも表示を確認する。共通の `scripts/shell-page-layout-helper.cjs` で割当領域・Slot・Viewの寸法、通知追加/削除、リサイズ/zoom、長いログの内部スクロールを確認する。実装時のレビュー・版更新・publishは[共通手順](development-workflow.md)に従う。
