# ショートカット画面の設計

## 現行: 0.26.23の実行順専用パネル

全コマンド一覧を維持し、設定上部と割り当てメニューからShortcutOrderDialogを開く。全提供元をまたぐ同一キーの割り当てを番号付きで並べ、ドラッグ・上下ボタン・Alt＋上下で順序を変更する。適用は共有draft、保存は全体toolbar。詳細は[実行順パネル](keybindings.md#実行順の専用パネル)を参照。


## 全コマンド一覧（0.26.22から）

2026-10-11の追加指定で、設定ページもApplet詳細と同じコマンド一覧と編集パネルを使う。現行仕様の正本は[条件付きショートカット](keybindings.md#編集画面と表示順)。以下の旧キー別グループ案は履歴であり、現在の画面へ戻す根拠にはしない。

- 設定ページは全通常コマンドを提供元をまたいで一覧表示し、未割り当ても残す。グループ分け/実行順番号/上下/ドラッグ/コマンド選択パレットは撤去する。
- 上部は簡潔な説明、総コマンド数、検索、割り当て状態の絞り込み、表示件数と解除を置く。検索欄と選択欄を同じ高さ・角丸で揃え、一覧も同じ配色と余白にする。
- ShortcutCommandListが2列のコマンド/割り当てと追加/編集/即時削除、フォーカス/スクロール復帰を担当する。AppletShortcutDialogは両画面から使い、ホストコマンドには提供元条件を出さない。
- ShortcutsEditorは全カタログの補完/検索/状態フィルター/登録エラーを担当。AppletShortcutOverviewは提供元コマンドと互換別名を分けて供給する。保存draftと実行処理は既存の共有セッションに保つ。
- hidden別名は既存の割り当てがある場合だけ表示し、未確認の保存済みコマンドも削除しない。表示順はカタログ順、実行順は保存配列順。一覧内には実行順操作を追加しない。0.26.23から専用パネルで編集する。
- 追加後は自動スクロールしない。フィルターは維持する。選択条件に合わなくなったコマンドが消えた場合、focusは一覧へpreventScrollで戻す。
- 検証は全コマンド/未割り当て/複数割り当て/未知・互換コマンド、検索/状態フィルター、直接追加/編集/削除/破棄/保存/再起動、実Windows登録競合/記録中表示維持/再試行、Applet側の回帰、両テーマと3幅を含める。

## 依頼された変更

- 設定ページとApplet詳細のショートカット画面を別の画面として設計する。
- 設定ページはキー単位にグループ化し、割り当てだけを表示する。空グループ・未割り当てコマンドは表示しない。
- 上部にはキー入力、特殊キー選択、いつ・どこで、割り当てを追加を置く。入力後にパレットでコマンドを選ぶ。追加時の自動スクロールは行わない（同日の追加指定）。
- キーグループの追加ボタンは、そのキーと既定の条件でコマンドを追加する。
- 行メニューは「実行順を上げる」「実行順を下げる」「コマンドの変更」「削除」の4項目にする。
- Applet詳細は作り直し、提供元の定義順でコマンドと割り当ての組を表示する。第一段階では表示専用とする。

以下の追加位置、検索、条件の引き継ぎなどは、この依頼を具体化する採用仕様である。

## 基本モデル

1つの割り当ては、安定ID・コマンド・キー・有効状態・いつ/どこでを持つ。既存の `Settings.keybindings` を正本とし、保存形式やdispatcherは変更しない。

グループの識別子は正規化したキーだけとする。提供元や条件が違っても、同じキーなら同じグループへ入れる。グループ内は保存配列から該当キーを取り出した順で表示する。

表示番号はグループ内で1から付ける。無効行や現在利用できないコマンドも順番を持つ。押下時は、この順番のうち有効・利用可能・条件一致の行が実行対象になる。同じコマンドが複数一致した場合は最初の一致位置で1回だけ実行する。条件は押下時に確定し、エラー継続・再入防止・終了/再起動の既存仕様を維持する。

## 設定ページ

### 全体配置

```text
ショートカットキー
説明: 同じキーの中で、条件に一致したコマンドを上から順に実行します。

[キー入力] [特殊キー ▼] [いつ・どこで ▼] [割り当てを追加]
                         [対象Applet選択: 必要なときだけ]

[コマンド・キー・提供元を検索] [すべて / 登録エラー]

Ctrl+Alt+K                                      [＋ 割り当てを追加]
順番   有効   コマンド              キーバインド   いつ・どこで   その他
⠿ 1    ON     コマンドA / 提供元A   Ctrl+Alt+K     AppDock全体    …
⠿ 2    ON     コマンドB / 提供元B   Ctrl+Alt+K     AppDock全体    …
⠿ 3    OFF    コマンドC / 提供元A   Ctrl+Alt+K     提供元A        …

F5                                             [＋ 割り当てを追加]
…
```

- キーグループは正規化したキー文字列の自然順で表示する。数値部分は数値として比較し、F2はF10より前とする。比較規則は固定し、実行順とグループ順を結び付けない。
- 既存の6列を維持する。各行のキー欄も残し、個別の割り当てを別のキーへ変更できる。コマンド欄には名前・提供元・完全なコマンドIDを表示する。
- 列幅は既存の固定colgroupを基礎とし、コマンド列を可変幅にする。狭幅では上部フォームを折り返し、一覧は内部横スクロールとする。
- グループを持たない初期状態では「ショートカットの割り当てがありません」と追加フォームを表示する。
- 無効行、停止中Applet、提供元不明の保存済み割り当てもキーのグループへ残す。「現在利用できません」等の状態とIDを表示し、編集・削除できる。
- 現在の「割り当て済み／未設定」の絞り込みは撤去する。正常な同キー重複やOS登録成功の表示を再追加しない。実際の登録エラーと再試行は維持する。

### 上部からの追加

1. キー入力ボックスでキーを記録するか、特殊キーを選ぶ。
2. 「いつ・どこで」を選択する。「指定したApplet」は1件以上の選択を必要とする。
3. 有効な入力が揃ったら「割り当てを追加」を有効にする。
4. 選択専用コマンドパレットを開く。本体と全Appletのコマンドを候補にする。登録済みで現在利用できないコマンドも選択できる。選択で実行しない。
5. 選択確定時に新しいIDの有効な割り当てを生成し、同じキーのグループの末尾へ追加する。既存の割り当てを自動統合しない。
6. パレットを閉じ、押した追加ボタンへスクロールを伴わずフォーカスを戻す。キー・条件・検索・エラー絞り込み・一覧の表示位置を保持する。追加行へ自動スクロールしたり、フォーカスを移したりしない。

追加元の近くに「Ctrl+Alt+KにコマンドAを追加しました」のような短い完了表示を出す。表示領域はあらかじめ確保し、連続追加でフォームや一覧を押し下げない。検索で追加行が見えなくても、自動で絞り込みを解除しない。新グループや行の挿入が表示位置より上で発生する場合も、元の表示位置を保つ。

キー入力・条件の作成途中はフォーム内だけの状態とし、共有設定draftへ空キーの行を追加しない。パレットのキャンセルでは設定を変更せず、入力内容を保持する。選択後もキーと条件を保持し、同じ条件の追加を繰り返せる。

特殊キーの選択肢は既存のTab / Ctrl+Tab / Ctrl+Shift+Tab / Escape / Enter / Space / Pauseを維持する。通常のTabはフォーカス移動、Escapeは記録終了とし、Deleteはキーとして記録できる。入力中の誤実行防止・IME保護も維持する。

### 追加時の条件

上部の条件初期値は「コマンドの既定」とする。これは作成フォーム専用の選択肢で、保存するscopeを増やすものではない。

| フォームの選択 | コマンド確定後の条件 |
| --- | --- |
| コマンドの既定 | Appletコマンドは提供元 `owner`、本体はAppDock全体 `app` |
| グローバル | `global` |
| AppDock全体 | `app` |
| すべてのApplet | `pages` |
| 指定したApplet | `applets` と選んだID群 |

ここでの「既定」は現在の新規割り当ての条件を指し、manifestの既定キー・既定条件を複製する意味ではない。パレット確定前に解決後の条件を分かるように表示する。既定の提供元には名前を使い、未選択時に特定Appletの名前を仮定しない。

グループの追加ボタンはキーをそのグループに固定し、条件は常に「コマンドの既定」でパレットを開く。上部フォームの条件や、そのグループの先頭行の条件を流用しない。

### 並べ替え・変更・削除

| 操作 | 挙動 |
| --- | --- |
| 実行順を上げる／下げる | 同じキーの直前／直後の行と入れ替える。先頭の上、末尾の下は無効 |
| ドラッグ／ハンドルの上下キー | 同じキーの中で移動する。異なるキーへのdropを受け付けない |
| コマンドの変更 | 全提供元を対象とした選択パレットを開き、選んだ行のコマンドを置換する |
| 削除 | 既存と同様に確認後、選んだ割り当てIDだけをdraftから除く |

- その他メニューは依頼された順の4項目だけにする。「複製」「既定に戻す」「キーのクリア」は表示しない。削除はコマンド自体の削除ではないことを確認文で示す。
- 最後の割り当てを削除するとキーグループも消える。未割り当てコマンドの代替行は作らない。保存後の再起動でも既定値を復活させない。
- コマンド変更ではID・キー・有効状態・グループ内の位置を維持する。`global/app/pages/applets` は対象IDを含めそのまま保持する。
- `owner` は「選んだコマンドの提供元」を意味するため、別Appletのコマンドへ変更したら新しい提供元へ変わる。本体コマンドへ変更する場合は `app` へ切り替える。この条件変化は選択候補の説明に表示する。キャンセルでは変更しない。
- 行のキーを変更したら、新しいキーのグループ末尾へ移し、その行へスクロールする。移動元が空なら消す。同じ正規化キーへの入力は順番を変えない。条件・コマンド・有効状態は保持する。
- 有効状態・条件だけの変更で順番を動かさない。同じキー・コマンド・条件の重複も勝手に削除せず、既存の1回実行ルールを適用する。

### 検索中の実行順

検索はキー・コマンド名・完全ID・提供元名を対象にする。該当する割り当てのあるグループを、全行表示する方式とする。キー一致ではグループ全体が該当し、コマンド一致では該当行を強調する。

登録エラーの絞り込みも、エラーのあるグループを全行表示する。隠れた同キー行を飛び越えて並べ替える問題を避け、表示された隣接行が実際の隣接行となる。番号は常にそのキーの全割り当てでの順番を示す。該当なしの場合は設定を空にした状態と区別する。

## Applet詳細: コマンド順の一覧

```text
ショートカット

コマンド                        割り当て
コマンドA                       Ctrl+Alt+K  · AppDock全体
at365.example.commandA          F5          · Example

コマンドB                       未割り当て
at365.example.commandB

コマンドC                       Ctrl+Alt+K  · Example  [無効]
at365.example.commandC
```

- 1コマンドを1行とし、右欄に各割り当ての「キー＋いつ・どこで」を1組ずつ縦に表示する。キーだけをまとめて条件との対応を失わせない。
- 提供中の全通常コマンドを列挙し、割り当て0件は「未割り当て」とする。コマンド0件なら「このAppletが提供するコマンドはありません」と表示する。
- 名前・完全ID・利用可否を表示する。無効な割り当ては除外せず「無効」と明示する。「指定したApplet」は対象名を列挙し、不明な対象はIDと未導入表示を残す。
- 一覧をコマンド名やキーでソートしない。`applet.commands` の通常コマンド順を使用する。現カタログはmanifest宣言順を保ち、未宣言の動的コマンドを登録配列順で末尾に追加している。同じIDのランタイム情報更新ではmanifestの位置を保つ。
- 動的コマンドの追加・置換は最新snapshotの順序へ追従する。停止後に宣言のない動的コマンドがカタログから消える場合、現在の提供コマンドとして推測して混ぜない。保存済み割り当ては設定ページに残す。
- hiddenの互換別名は通常コマンド一覧に混ぜない。ただしその別名に保存済み割り当てがある場合は、末尾の「互換コマンドへの割り当て」にIDと組を表示し、割り当てを見失わせない。第一段階で別名を正規IDへ書き換えない。
- 1コマンド内の割り当ては既存の保存配列順に列挙する。この順序を編集する機能や、異なるキー間の実行順番号は設けない。
- データは共有設定draftから読む。設定ページでの未保存変更も見え、保存・破棄で同じ内容に揃う。別draftは作らない。
- 0.26.19では表示専用。0.26.20から以下の編集パネルを追加する。既存の全体保存toolbarとタブ選択保持は維持する。

組み込みの「WebApplet」管理項目はコマンド提供元ではなく、新規サイト用テンプレートの管理画面である。一覧とパネルは通常Appletと各Webサイトの詳細が対象。管理項目のテンプレート編集はそのまま維持する。

### 0.26.20: 必要時だけ開く編集パネル

- コマンド横の＋で追加、キーと条件の組をクリックして編集。その他メニューは「編集」「削除」のみ。0.26.21から削除は確認なしで選んだIDだけを共有draftから除く。保存前は全体の変更破棄で戻せる。未割り当てと割り当て済みのキーの左端を揃える。利用不可・無効・互換別名の行も編集できる。
- 一覧を押し下げない小さなmodal dialogを表示する。ネイティブdialogのフォーカス制限を使い、閉じると元の操作ボタンへpreventScrollで戻す。追加後も一覧のスクロール位置を保つ。
- キーをキーキャップで大きく表示する記録欄へ初期フォーカス。特殊キーの選択欄は必要時だけ展開し、Ctrl/Alt/Shiftの選択と操作/移動/F1〜F24のボタンを組み合わせる。選択後は折りたたみ記録欄へ戻す。
- Tab/Shift+Tabはフォーカス移動、Escapeは取消。記録欄のEnter/Delete/Spaceは割り当てるキーとして扱い、適用はボタンで行う。Tab/Escapeとその組み合わせは特殊キーからも選べる。IME変換・修飾キーだけ・Windowsキーは割り当てにしない。
- dialog全体で画面ショートカットを抑止し、表示中はグローバル登録を一時解除する。解除完了前は記録と適用を受け付けず、ウィンドウ再フォーカス時も解除を確認する。終了/unmount時は登録を復帰する。
- いつ・どこでと有効状態を変更可能。新規はowner/有効、既存は現在値を維持。空キーや対象Appletが0件の条件では追加/適用できず、不完全な行を共有draftへ作らない。
- 追加/適用は最新の共有draftへ反映し、保存は既存toolbarで行う。開いた後に元の割り当てが外部更新・削除された場合は上書きせず開き直しを案内する。他の編集を巻き戻さない。
- 追加とキー変更は同キー末尾、条件/有効状態だけの変更は位置を保持する。実行順の編集・並べ替え・その画面への導線は今回追加しない。コマンドの提供元定義順を維持する。

## 実装設計

### コンポーネントの責務

| 対象 | 方針 |
| --- | --- |
| `ShortcutsEditor.tsx` | 設定ページ専用にする。ownerによる画面切り替えを廃止し、キーグループ・追加フォーム・行編集を管理 |
| `AppletShortcutOverview.tsx` | Applet詳細専用。コマンド順の一覧と追加/編集/削除。共有draftへ変更を反映 |
| `AppletShortcutDialog.tsx` | 一時入力、キー記録、特殊キー選択、条件/有効状態、フォーカスと登録解除の寿命を管理 |
| `AppletSettingsPanel.tsx` | ショートカットタブを新一覧へ置換し、一括初期化と旧編集画面の組み込みを除く |
| キー入力・条件選択の小部品 | 上部作成フォームと設定ページ内の行で再利用できる単位へ分離 |
| `BindingActions.tsx` | popup配置、キー操作、削除確認を再利用。ショートカット側が4項目を指定できるようにする |
| `CommandPalette.tsx` | 選択モードを再利用。コマンド変更時の条件プレビューと、閉じた後のフォーカス移動を調整 |
| `shared/keybindings.ts` | キー別グループ生成、同キー移動、末尾追加、キー変更時の移動、コマンド変更の純粋関数を用意 |

画面コンポーネントは共通化しない。設定データの取得・キー表記・条件のラベル解決などの小さな処理は共用してよい。ジェスチャーのメニュー内容・並べ替え範囲は変更しない。

### 保存配列を扱う規則

- 並べ替えでは対象キーが占める配列内の位置だけを入れ替える。他キーの行とその相対順を維持する。
- 新規追加は、そのキーの最後の行の直後へ挿入する。既存行がなければ配列末尾へ追加する。
- キー変更は対象行を抜き、新しいキーへ更新してから移動先の最後へ挿入する。安定IDは維持する。
- 表示グループ順を理由に保存配列を並べ直さない。初回表示で設定を変更しない。既存の同キー実行順をそのまま引き継ぐため、設定移行は不要。
- 条件やコマンド変更で旧互換フィールドを直接編集せず、既存の `withKeybindings` を通して派生値を更新する。
- UIの追加フォームや検索だけではdirtyにしない。パレット選択時に最新draftを基準に更新する。開いている間に行が削除・破棄された場合、古い行を復活させず操作を取り消す。
- 追加パレットは元ボタンへ `focus({ preventScroll: true })` で戻す。背景一覧のスクロール位置と表示中の基準要素を保持し、DOMの挿入で位置がずれる場合も補正する。追加後の行へのfocus・scrollは実装しない。パレット内の候補ナビゲーションとは別に扱う。
- 既存行のキー変更で別グループへ移す際の位置案内は追加とは別の操作とし、安定IDで対象を探す。移動後にキー記録へ自動で入り直さない。

### 保存と異常系

共有の `useSettingsEditor`、JSON編集、revision競合検出、保存/破棄、未保存通知を維持する。追加フォームでは不完全な行を生成しないが、JSONや既存行の条件編集の不正値は従来どおり保存を拒否する。

有効な保存済み設定に空キーは存在しない。JSONが不正な状態からフォームへ入れない既存導線を維持し、不正な行を非表示にして保存してしまわない。上限2000件に達した場合は追加を無効にして理由を示す。削除・修正は可能にする。

## 実装の進め方と受け入れ確認

1. キー単位の純粋関数と表示モデルを用意し、混在提供元・混在キーの順序保持を確認する。
2. 設定ページのグループ・作成フォーム・4項目メニュー・追加時の表示位置保持を実装する。
3. Applet表示専用一覧を新設し、旧画面との共用を解消する。
4. 旧Appletグループを前提にする試験と文書を更新し、対象の動作試験を実施する。
5. 実装完了時は共通作業手順に従い本体の版更新・本体publish・固定発行EXEの確認を行う。

受け入れ確認:

- 別AppletのA/B/Aという同キー割り当てが保存順に見え、上下・ドラッグの両操作で実際の呼び出し順も変わる。
- 条件の違う同キー行を別グループに分けず、条件一致行だけが既存規則で実行される。同一コマンド重複は1回。
- 無効行を含む番号、先頭/末尾の操作制限、他キーへのdrop拒否、検索中の全行表示を確認する。
- 上部追加・グループ追加・キャンセル・キー変更・コマンド変更・最後の行の削除が定義どおりである。
- 提供元条件から別Applet/本体へコマンドを変更したときの説明と保存条件が一致する。
- Applet画面は宣言順/動的追加順、複数割り当て、未割り当て、無効、停止、互換別名、コマンド0件を正しく表示する。
- 表示だけではdirtyにならず、共有draftの変更・保存・破棄・JSON・外部変更競合・再起動で割り当てと順序が保たれる。
- パレット選択でコマンドを実行せず、記録後にグローバル入力が復帰する。上部/各グループから連続追加しても表示位置・入力・絞り込みを保持し、元ボタンへフォーカスが戻る。表示中の位置より前に新グループが挿入されるケースも確認する。
- キー変更時の位置案内、狭幅・両テーマ・キーボード操作を確認する。
- WebAppletの管理テンプレートとジェスチャーの既存操作を維持する。

主な既存試験は `tests/keybindings.test.cjs`、`tests/dynamic-commands.test.cjs`、`scripts/shortcuts-ui-test.cjs`、`scripts/keybindings-ui-test.cjs`、`scripts/applet-order-ui-test.cjs` と関連navigation/gestures GUI。実施した検証と未確認範囲は[検証記録](../VERIFICATION.md)へ記録する。
