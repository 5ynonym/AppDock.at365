# インフォメーション通知と操作結果の統合

## 設定と分類

本体の通知設定を「エラー通知」「警告通知」「インフォメーション通知」の順にする。
情報通知は `host / information / operation-completed`、info、既定ON、バナーのみ、6秒、読み上げOFF、永続履歴とする。
警告と情報はエラーと同じ `requiredTargets: ['banner']` を使う。通知全体のOFFは設けず、バナー解除とセンターのみを拒否する。
旧設定のバナー不足は実効方針で補完し、読み込みだけで保存しない。警告の状態寿命・閉じた後の再表示抑止は変更しない。

## 発行と移行範囲

本体内部のInformationReporterから既存TypedNotificationsへ発行する。操作の完了地点でイベントIDを決め、同じイベントの再報告を抑止する。共通ログも残し、設定の変更・画面再表示・状態照会で過去の結果を再発行しない。通知障害を元の処理の失敗にしない。MCP/一般Appletへ任意の本体情報通知APIは追加しない。

- 手動更新確認の更新有無・対象なし・取消は情報通知。更新画面への操作を付ける。最終失敗は共通ErrorReporterへ接続し、詳細は更新画面に保持する。起動時の既存「更新のお知らせ」と更新適用完了の種類は維持する。
- Codex連携の接続テスト成功、登録・解除・再発行・コピー・既存の明示保存結果を情報通知へ移す。テスト成功はAppDock内部の疎通のみを意味し、Codexからの実接続を保証しない。テスト失敗は固定の安全な原因・対処を共通エラー通知と戻り値へ揃える。状態照会・変更なしは通知しない。
- 操作許可の保存、TTSキーの保存・削除、試聴受付・停止、Webアカウントの追加・名前変更・削除・クリアを移す。削除確認の取消は成功通知しない。完了前に成功を出さない。読み上げ停止の結果通知を理由に音声を再開しない。通常の即時保存や入力中のモデル候補取得へ通知を増やさない。
- 既存の下側「コマンドを実行しました」を本体の対応するUI操作完了から通知する。機能固有の結果がある更新操作等は二重通知しない。

通知・保存履歴・読み上げには、固定の説明と必要最小限の件数のみを使う。APIキー、トークン、URL、アカウント名、ローカルパス、例外本文を入れない。入力エラーと設定画面の診断表示は残す。

## 下側表示と検証

rendererの汎用toastとCSSを撤去する。UpdateProgressは処理中の進捗とキャンセル操作だけを表示し、完了結果をステータスバーへ重ねない。更新結果の詳細は更新画面、共通通知、履歴から参照する。

設定順・既定6秒・必須バナー・旧OFF設定の無効化・旧設定補完、同一イベント抑止、報告障害、通知文の安全性、接続テスト成功/失敗、手動更新結果、Webアカウント保存・取消、下側表示の撤去と進捗維持を検証する。実測と発行版はVERIFICATIONへ記録する。
