# 更新配布先の確認手順

実装後のGitHub・HTTP(S)・UNCの実配布先確認用です。各項目の結果を記録してください。ローカルHTTPの隔離試験は済んでいますが、実際の公開先・ネットワーク共有での確認は別です。通常操作は[README](../README.md#アップデート)、生成方法は[開発ガイド](updates.md)を参照してください。

## 1. 今回の発行物を用意する

AppDockは0.23.0です。単一EXE形式を維持しています。Applet本体の版は今回変更していません。

| 対象 | 配布元へ置くファイル | ローカル更新元の指定例 |
| --- | --- | --- |
| AppDock | `publish/AppDock.at365.exe` と `publish/update.json` | `A:\30.PROJECT\AppDock.at365\publish` |
| 各Applet | そのリポジトリの `publish/update.zip` と `publish/update.json` | `A:\30.PROJECT\Applet.Watch.at365\publish` |

Appletの初回追加は、従来どおり`publish/各Applet名`の中身を配置します。更新ボタンはインストール済みAppletを対象にします。ZIPは各リポジトリで同名なので、別AppletのJSON/ZIPを混ぜないでください。

同じバージョンを試す場合は「更新の設定 → 同じバージョンの再適用」をONにして保存し、確認が終わったらOFFへ戻します。旧版への更新はできません。

## 2. 配布先を用意して更新元を保存する

必要な配布先から順に確認できます。ファイルは同じ発行で生成した組み合わせを使い、JSONを最後に配置します。

- **ローカル**: 上の`publish`フォルダーを指定します。Appletでは従来の`publish/各Applet名`も指定できますが、更新ZIPの確認ではJSON/ZIPがある親の`publish`を使います。
- **UNC**: `\\server\share\AppDock`やAppletごとのフォルダーに必要な2ファイルを置き、そのパスを指定します。AppDockを実行するユーザーから読み取れることを確認します。
- **HTTP(S)**: 同じWebフォルダーへ2ファイルを置き、`https://example.test/AppDock/update.json`または末尾が`/`のフォルダーURLを指定します。閲覧用のHTMLページではなくファイル本体が取得できるURLを使います。
- **GitHub**: 対象リポジトリの正式なReleaseへ上の2ファイルをassetsとして添付します。AppDockの更新元はAppDockリポジトリ、Appletの更新元は各Appletのリポジトリを指定します。`github:owner/repo`またはリポジトリ/ReleaseのURLを使えます。自動生成のSource code ZIPは更新用ZIPではありません。非公開認証とプレリリースには対応しません。

本体は「更新の設定」、Appletは「インストール済みのApplet → 更新元の設定」から指定し、「変更をすべて保存」を押します。既定に戻す操作も保存が必要です。この手順書の作成時点で、外部公開や実利用先への配置は実行していません。

## 3. 確認だけの操作

- [ ] 「更新を確認」で、対象の版と更新可能/同じ版などの結果が表示される。
- [ ] 確認だけでは本体/Appletが置き換わらず、再起動しない。
- [ ] 更新元を読めない場合は対象に理由が表示され、設定を直して再確認できる。
- [ ] Appletの無効状態でも確認でき、更新確認だけで有効にならない。

## 4. 更新とキャンセル

- [ ] AppDockの更新を開始すると進捗が表示され、取得が長ければ容量と割合が増える。
- [ ] 取得中の「キャンセル」で通常操作へ戻り、現在の版を保持する。再試行できる。
- [ ] 最終確認の対象・版が正しく、そこでキャンセルした場合も現在の版を保持する。
- [ ] 「更新して再起動」の後、同じ配置先の単一EXEから起動し、版が想定どおりになる。
- [ ] トレイ開始の設定がONでも、更新後は更新前のページを表示する。
- [ ] 保存済み設定・Applet有効状態・既存ログインが保持される。
- [ ] Applet一括更新では対象が正しく、再起動が1回で済む。必要な本体版が不足する候補は案内される。
- [ ] Applet個別更新では選んだAppletだけを更新する。

準備が速い小さいファイルではキャンセル可能な表示時間も短くなります。確定後の交換中にキャンセルする操作はありません。実ファイルを強制終了して壊す試験は、この手順には含めません。

## 5. 起動時確認と設定の復帰

- [ ] 本体/各Appletの起動時確認と待ち時間を保存し、通常起動すると指定後に結果を確認できる。
- [ ] 起動時には更新情報の確認だけを行い、配布EXE/ZIPの取得・交換・再起動は行わない。
- [ ] 通知ON/OFFが希望どおりに働く。
- [ ] 本体とAppletの更新元を「既定に戻す」→保存で戻せる。空欄を保存した対象は更新確認を無効にできる。
- [ ] 試験用の「同じバージョンの再適用」や起動時設定を普段使いたい値へ戻す。

実際に確認した配布先、対象の版、結果を記録すれば完了です。
